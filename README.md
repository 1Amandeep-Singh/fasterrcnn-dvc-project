# Object Detection with Faster R-CNN — DVC + TensorBoard + FastAPI + Postman

End-to-end, reproducible object detection pipeline: DVC orchestrates data
prep → training → evaluation as versioned stages, TensorBoard visualizes
training in real time, and a FastAPI service exposes the trained model
for inference, testable directly from Postman.

## Project layout

```
.
├── data/
│   ├── raw/
│   │   ├── images/                 # your source images (DVC-tracked)
│   │   └── annotations/
│   │       └── instances.json      # COCO-format annotations (DVC-tracked)
│   └── processed/                  # generated by the `prepare` stage
├── src/
│   ├── utils.py                    # config loading, seeding, device selection
│   ├── dataset.py                  # COCO-format PyTorch Dataset
│   ├── model.py                    # torchvision Faster R-CNN builder
│   ├── prepare_data.py             # DVC stage: train/val split
│   ├── train.py                    # DVC stage: training + TensorBoard logging
│   └── evaluate.py                 # DVC stage: COCO mAP evaluation
├── app/
│   ├── main.py                     # FastAPI inference service
│   └── schemas.py                  # request/response models
├── postman/
│   └── FasterRCNN_API.postman_collection.json
├── models/                         # DVC-tracked trained weights (output)
├── metrics/                        # DVC-tracked metrics json (output)
├── logs/tensorboard/               # DVC-tracked TensorBoard logs (output)
├── params.yaml                     # single source of truth for all config
├── dvc.yaml                        # pipeline stage definitions
└── requirements.txt
```

## 1. Setup

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

git init
dvc init
```

Configure a DVC remote for your data/model artifacts (S3, GCS, Azure, or a
local/NFS path all work — example with local storage):

```bash
dvc remote add -d storage /path/to/shared/dvc-storage
```

## 2. Add your data

Put your images in `data/raw/images/` and a single COCO-format annotations
file at `data/raw/annotations/instances.json`. Track them with DVC instead
of git so large binaries never bloat your repo:

```bash
dvc add data/raw/images
dvc add data/raw/annotations/instances.json
git add data/raw/images.dvc data/raw/annotations/instances.json.dvc .gitignore
git commit -m "Track raw dataset with DVC"
```

Adjust class count and hyperparameters in `params.yaml` — in particular set
`train.num_classes` to (number of object categories + 1 for background).

## 3. Run the pipeline

```bash
dvc repro
```

This executes, in dependency order, only the stages whose inputs changed:

| Stage      | What it does                                              | Outputs (DVC-tracked)                          |
|------------|-------------------------------------------------------------|-------------------------------------------------|
| `prepare`  | Splits COCO annotations into train/val by image             | `data/processed/{train,val}.json`               |
| `train`    | Trains Faster R-CNN, logs losses to TensorBoard every N steps | `models/fasterrcnn_model.pth`, `metrics/train_metrics.json`, `logs/tensorboard/` |
| `evaluate` | Computes COCO mAP/AR on the val split                        | `metrics/eval_metrics.json`                     |

Visualize the DAG and inspect metrics:

```bash
dvc dag
dvc metrics show
dvc metrics diff        # compare against a previous git commit/experiment
```

Re-running after a `params.yaml` edit (e.g. more epochs) only re-executes
the affected stages — DVC hashes inputs/params to decide what's stale.

## 4. Watch training in TensorBoard

While `dvc repro` is training (or after it finishes), point TensorBoard at
the log directory declared in `params.yaml`:

```bash
tensorboard --logdir logs/tensorboard --port 6006
```

Open `http://localhost:6006` to see:
- `train/total_loss` and the four Faster R-CNN loss components (RPN objectness,
  RPN box regression, ROI classification, ROI box regression)
- `train/learning_rate` schedule

## 5. Version everything with git + DVC together

```bash
git add dvc.yaml dvc.lock params.yaml metrics/ src/ app/ postman/
git commit -m "Train Faster R-CNN v1"
dvc push       # pushes data/model binaries to the DVC remote
git push       # pushes code + small metadata (.dvc files, dvc.lock) to git
```

Anyone can now reproduce your exact result with:

```bash
git clone <repo> && cd <repo>
dvc pull       # fetches data + trained weights from the remote
dvc repro      # re-runs only what's missing/changed
```

## 6. Serve the model with FastAPI

```bash
uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload
```

- Interactive docs: `http://localhost:8000/docs`
- `GET /health` — confirms the model loaded and reports the inference device
- `POST /predict?score_threshold=0.5` — multipart file upload, returns boxes/labels/scores

## 7. Test the API with Postman

1. Open Postman → **Import** → select `postman/FasterRCNN_API.postman_collection.json`.
2. Confirm the `base_url` collection variable matches where uvicorn is running
   (default `http://localhost:8000`).
3. Run **Health check** first to confirm `model_loaded: true`.
4. Run **Predict (upload image)** — in the Body tab, click the `file` field
   and select a local test image, then Send.
5. Response shape:

```json
{
  "filename": "test.jpg",
  "image_width": 640,
  "image_height": 480,
  "inference_time_ms": 142.3,
  "detections": [
    { "label_id": 1, "label_name": "widget", "score": 0.93, "box": [102.4, 55.1, 310.7, 400.2] }
  ]
}
```

## Design notes / why this structure

- **DVC over plain scripts**: `dvc.yaml` declares data/param dependencies
  explicitly, so `dvc repro` skips stages that don't need to re-run, and
  `dvc.lock` gives you an exact, hashed record of which data + code + params
  produced any given model — critical for reproducing or auditing results later.
- **Params centralized in `params.yaml`**: every stage and the FastAPI app
  reads from the same file, so there's one place to change class count,
  learning rate, or paths without hunting through code.
- **TensorBoard over print statements**: loss curves reveal problems (LR too
  high, RPN not converging, box regression diverging) far earlier than
  scrolling logs.
- **Model loaded once at FastAPI startup**, not per-request — this is what
  makes the service "high-performance": no repeated disk I/O or weight
  deserialization on the hot path.
- **Postman collection checked into the repo**: anyone pulling the project
  can test the API within a minute without hand-building multipart requests.

## Extending this

- Swap `resnet50_fpn` for `resnet50_fpn_v2` or a lighter backbone (`mobilenet_v3_large_fpn`)
  in `src/model.py` for a speed/accuracy trade-off.
- Add a `dvc.yaml` `export` stage that converts `fasterrcnn_model.pth` to
  ONNX/TorchScript for faster CPU inference in `app/main.py`.
- Add DVC experiments (`dvc exp run --set-param train.learning_rate=0.01`) to
  sweep hyperparameters without polluting git history until you find a winner.
